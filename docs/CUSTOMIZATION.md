# Customizing SpecKit PowerPack

PowerPack is designed so projects customize **configuration, policy, gates and domain skills**, not generated agent copies of PowerPack commands.

```text
PowerPack invariant
      +
project configuration
      +
stricter project/domain policy
      =
effective behavior
```

Project customization may add constraints or become stricter. It must not weaken same-SPEC safety, mandatory review findings, evidence contracts, capability-driven execution, debt creation rules or explicit update confirmation.

## Installed customization surface

```text
.specify/powerpack/
├── bin/
│   ├── powerpack.py
│   ├── capabilities.py
│   ├── review_protocol.py
│   ├── debt.py
│   └── full_cycle.py
├── model-routing.json
├── prerequisites.json
├── quality-gates.json
├── review.json
├── full-cycle.json
├── technical-debt.json
├── update.json
├── deep-review-protocol.md
├── technical-debt-policy.md
└── technical-debt-template.md
```

Global machine-local Web identity lives outside the repository under the platform-native PowerPack config root.

## Configuration map

| Concern | Project-local location | Package source | Customization rule |
|---|---|---|---|
| model/integration routing | `.specify/powerpack/model-routing.json` | `assets/config/default-model-routing.json` | safe to tune stage profiles; do not weaken independent reviewer contract |
| predecessor graph | `.specify/powerpack/prerequisites.json` | generated by `cli.py` | may add prerequisites; do not bypass same-SPEC evidence to make a phase run |
| quality/build gate | `.specify/powerpack/quality-gates.json` | generated by `cli.py` | use explicit `custom_command` for unsupported/ambiguous architecture |
| review behavior | `.specify/powerpack/review.json` | `assets/config/default-review.json` | mode/Web/project selection/profile; approval evidence remains mandatory |
| review methodology | `.specify/powerpack/deep-review-protocol.md` | `assets/review/deep-review-protocol.md` | add stricter/domain probes; do not weaken required fronts/approval proof |
| full-cycle orchestration | `.specify/powerpack/full-cycle.json` | `assets/config/default-full-cycle.json` | mode, optional phases, round limits; non-weakenable safety fields remain fixed |
| technical debt | `.specify/powerpack/technical-debt.json` | `assets/config/default-technical-debt.json` | backlog/prefix/project policies; project policies may only strengthen the floor |
| update behavior | `.specify/powerpack/update.json` | `assets/config/default-update.json` | checks/source/ref/project refresh; explicit force/reset confirmation remains mandatory |
| browser identity | global config + `browser-profiles/<platform>/...` | `src/speckit_powerpack/cli.py` | use CLI login/bind commands; never copy profile directories across platforms |

# Skill-by-skill guide

## `speckit-implement`

**Purpose:** wrap official Spec Kit implementation and record a precise same-SPEC before/after delta.

Package command:

```text
src/speckit_powerpack/assets/presets/powerpack-core/commands/speckit.implement.md
```

Runtime:

```text
package:   src/speckit_powerpack/assets/runtime/powerpack_runtime.py
installed: .specify/powerpack/bin/powerpack.py
```

Customize implementation intent through SPEC/plan/tasks/project instructions. Do not add language/framework-specific file accounting to this skill; workspace delta semantics are generic.

## `speckit-checklist-converge`

**Purpose:** converge checklist/requirements quality after a real checklist execution for the same SPEC.

Package command:

```text
assets/presets/powerpack-core/commands/speckit.checklist-converge.md
```

Configuration:

```text
.specify/powerpack/prerequisites.json
```

Customize checklist content/templates/project policy. The same-SPEC predecessor rule is a PowerPack invariant.

## `speckit-converge`

**Purpose:** reconcile implementation against SPEC/plan/tasks.

Package command:

```text
assets/presets/powerpack-core/commands/speckit.converge.md
```

Project-specific closure checks belong in project policy/gates. For example, a Spring-controller-to-React-screen traceability script is valid project logic; it should not become a framework assumption in PowerPack.

An active convergence gap is not debt merely because the operator wants to finish the cycle.

## `speckit-implement-review`

**Purpose:** independent deep technical review after implementation.

Canonical package command:

```text
assets/presets/powerpack-core/commands/speckit.implement-review.md
```

There is exactly one canonical asset. `speckit.implement-review-v2.md` was transitional and must not exist.

Runtime/configuration:

```text
.specify/powerpack/bin/powerpack.py
.specify/powerpack/bin/review_protocol.py
.specify/powerpack/review.json
.specify/powerpack/model-routing.json
.specify/powerpack/quality-gates.json
.specify/powerpack/deep-review-protocol.md
```

Safe customization:

- interactive/auto behavior;
- Web gate enablement/project selection;
- explicit quality gate for an unsupported project;
- stricter project/domain review probes;
- project constitution/architecture/security invariants.

Non-weakenable invariants:

- Claude executor → exactly one external Codex deep reviewer;
- Codex executor → current Codex session, no recursive Codex spawn;
- review bound to current immutable snapshot/head;
- every previous finding revalidated;
- complete snapshot re-reviewed after corrections;
- adversarial verdict challenge;
- changed-file/requirement/baseline/front evidence;
- validator-approved `APPROVED` contract;
- findings remain current-flow durable tasks, never debt/backlog escape hatches.

### ChatGPT Web review profile customization

Profiles are platform-scoped:

```text
browser-profiles/
├── windows/work/
├── linux/work/     # WSL
└── macos/work/
```

Bind each platform independently when authentication/project access differs:

```bash
speckit-powerpack review auth login work
speckit-powerpack review project bind my-project 'https://chatgpt.com/g/g-p-.../project' --profile work
speckit-powerpack review project use my-project
speckit-powerpack review project list --all-platforms
```

Never customize Web auth by copying a Windows persistent profile into Linux/WSL/macOS or vice versa.

## `speckit-full-cycle`

**Purpose:** orchestrate existing Spec Kit/PowerPack primitives for exactly one SPEC.

Package command:

```text
assets/presets/powerpack-core/commands/speckit.full-cycle.md
```

State runtime:

```text
package:   assets/runtime/powerpack_full_cycle.py
installed: .specify/powerpack/bin/full_cycle.py
state:     .specify/powerpack/runtime/full-cycle/<spec>.json
```

Configuration:

```text
.specify/powerpack/full-cycle.json
```

Safe customization:

- `interactive`/`auto`;
- optional phase enablement;
- max convergence attempts;
- max review attempts.

Non-weakenable runtime assertions:

```json
{
  "same_spec_only": true,
  "stop_on_blocked": true,
  "allow_debt_escape_hatch": false
}
```

The runtime controls the current phase and return target (`implement -> converge` or `implement -> implement_review`). A blocked cycle requires explicit `resume --unblock`; an agent cannot advance through the blocker by interpretation.

See [`FULL_CYCLE.md`](FULL_CYCLE.md).

## `speckit-debt-create`

**Purpose:** record only legitimately deferrable engineering work.

Package command:

```text
assets/presets/powerpack-core/commands/speckit.debt-create.md
```

Runtime:

```text
package:   assets/runtime/powerpack_debt.py
installed: .specify/powerpack/bin/debt.py
```

Configuration/policy:

```text
.specify/powerpack/technical-debt.json
.specify/powerpack/technical-debt-policy.md
project_policy_paths[]
```

Projects may customize backlog path, ID prefix, owners/domains and stricter required evidence. They may not make active review findings, convergence gaps, P0/BLOCKER or current SPEC obligations deferrable.

## `speckit-debt-list`

Read-only canonical inventory through:

```bash
python .specify/powerpack/bin/debt.py list
```

Projects may add presentation/grouping rules. Listing must not mutate status/readiness.

## `speckit-debt-consult`

Exact-ID read-only inspection through:

```bash
python .specify/powerpack/bin/debt.py consult <TD-ID>
```

Project policy may add governance interpretation. Historical policy conflicts should be reported, not silently rewritten.

## `speckit-debt-start`

Transitions only `OPEN + READY` items into `IN_PROGRESS` and appends provenance. Starting debt does not automatically create a SPEC. Projects may require stricter readiness or grouped-capability rules.

## `speckit-debt-close`

Requires objective proof against original resolution criteria and stricter project policy. The runtime requires explicit criteria satisfaction + evidence and preserves lifecycle history.

When executable validation applies, use capability-selected gates; do not embed Maven/npm/etc. in the debt skill.

See [`TECHNICAL_DEBT.md`](TECHNICAL_DEBT.md).

## `speckit.powerpack-tools.update`

**Purpose:** check/update the installed CLI and rematerialize managed PowerPack assets with explicit operator control.

Agent command:

```text
assets/extensions/powerpack-tools/commands/update.md
```

Core implementation:

```text
src/speckit_powerpack/update_manager.py
src/speckit_powerpack/cli.py
```

Project config:

```text
.specify/powerpack/update.json
```

Safe customization:

- enable/disable auto-check on installer runs;
- repository/ref/channel selection;
- whether a successful CLI update should refresh project materialization.

Non-weakenable safety:

- update check is read-only;
- normal apply requires confirmation unless the operator explicitly passed `--yes`/`--yes-update`;
- `--force` is never inferred by the agent;
- `--reset-config` is never inferred and requires `--force --yes`;
- even forced update never runs destructive Git operations or deletes project code, debt history or Web authentication profiles.

For a corrupted project materialization, use:

```bash
speckit-powerpack update . --project-only --force --yes
```

See [`UPDATES.md`](UPDATES.md) for the detailed update process diagram and node/file map.

## `powerpack doctor`

Implementation:

```text
src/speckit_powerpack/cli.py
assets/extensions/powerpack-tools/commands/doctor.md
```

Projects normally extend diagnostics with local skills. Change PowerPack doctor only when the reusable PowerPack installation contract changes.

# When to create a project-local skill

Create a local skill when the rule is about a product/domain/environment that is not universally true.

Good local examples:

- WASAPI/MMDevice audio lifecycle;
- trading risk/reconciliation rules;
- Oracle APEX metadata constraints;
- endpoint-to-screen traceability for a specific architecture;
- WSL-first development policy;
- proprietary contract/versioning governance.

Prefer PowerPack for reusable behavior across unrelated projects:

- same-SPEC receipts;
- review evidence contracts;
- technical-debt lifecycle semantics;
- full-cycle state/orchestration;
- capability-driven gates;
- platform-scoped browser identity;
- provider/executor routing;
- safe update/recovery mechanics.

# Upgrade/customization rule

Do not hand-edit generated/materialized `.claude/skills/*` or `.agents/skills/*` as a durable customization source. Change project configuration/policy or PowerPack package source and rematerialize it.

Normal update preserves project configuration:

```bash
speckit-powerpack update . --yes
```

A project config reset is an explicit recovery operation, not a normal upgrade:

```bash
speckit-powerpack update . --project-only --force --reset-config --yes
```
